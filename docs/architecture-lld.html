01

Agent modules

One Tauri process. React windows talk to the Rust core only over IPC. Every module that observes something writes an event to the local outbox, and only sync and uploader talk to the network. That one rule is what makes offline work and replays safe.

ModuleOwns
policyOrg policy cached on disk with its version. Replaced when a heartbeat reply carries a newer version.
activityPolls idle time every 5 s; emits idle_start/end at the threshold, lock/sleep and call events (camera, mic, screen share and presentation each start and end a call, so In meeting holds while any is on), and closes an app_session on every foreground change.
sessionShift state machine (section 2). Auto clock-in on first input inside the shift; auto clock-out after 30 min without input past shift end.
schedulerDraws next_at uniformly in [min, max] and writes it to disk before arming, so a restart keeps the same time. Applies deferral and lock rules. A due check-in held for a call, share or presentation leaves one deferred check-in (due time and deferral_reason call | screen_share | presenting; no capture); the card still follows once the hold ends.
checkinBuilds the challenge (target number, three shuffled buttons) and the card's look (size and style vary a little, CHK-15), validates clicks in Rust, rejects injected clicks, records response_ms, the outcome and the anti-cheat flags (synthetic clicks, VM, remote session).
anticheat, frame_hashVirtual-camera and VM name tables; a 256-bit perceptual hash of each pass's webcam frame, compared on the device with the last 20 passes' (kept only in the outbox's encrypted state). Only the flag (duplicate_frame:<bits>) is sent (ANT-05..07).
captureScreens (one per display), one webcam frame, excluded-app placeholders, blur, downscale, WebP. Writes files to the uploads table, never sends them itself.
syncDrains events in seq order, heartbeats every 60 s, applies the reply (acks, clock offset, policy, commands).
uploaderUploads a file only after its check-in event is acked, deletes the local copy on success.
authPKCE sign-in through the system browser and deep link; refresh token in the OS keychain.
updaterSigned update manifests from R2 per channel (pilot, stable); never updates during a shown check-in.

State machines

Two machines run on the device. The shift machine decides whether anything is collected at all; the check-in machine runs only while the shift is in Working.

Sync protocol

Events and files leave the device in two separate queues. Files wait for their event so that Storage can check, at upload time, that the check-in really passed.

04

API contract

All writes are Postgres functions called through PostgREST (POST /rest/v1/rpc/<name>) with the caller's JWT. They are SECURITY DEFINER, validate everything themselves, and are the only way to change data. Reads go straight to tables and views through row-level security.

06

Timesheet engine

buildSegments() in packages/core is a pure function from one user-day of events to a list of segments. The example below is a real morning run through it.

  1. Load the user-day: events whose time falls in the employee's local calendar day, plus any open interval from the day before.
  2. Build clocked-in intervals from clock_sessions and approved manual_entries.
  3. Cut them at every boundary from breaks, pauses, status periods, check-ins and project switches, giving atomic intervals.
  4. Classify each atomic interval by precedence: break, pause, offline, away (locked), unverified, meeting, idle, verified.
  5. Split pauses at the per-pause and per-day caps; the part over the cap becomes flagged pause.
  6. Attach the project in force at that moment, or Unassigned.
  7. Merge neighbours with the same type and project, apply exclusions from timesheet_edits.
  8. Inside one transaction holding an advisory lock on (user, day): delete the day's segments, insert the new ones, clear the dirty flag.
Invariants, checked by property tests with fast-check: segments never overlap; together they exactly cover clocked-in time plus approved manual time; totals equal the sum of raw seconds; running the function twice on the same input gives identical output; adding an event can only change segments that overlap it.

Access control

One SQL function, can_view_user(viewer, employee), backs every read policy and the capture-url check. Approval rights use a stricter variant that leaves admins out.

-- Agents may upload only into their own folder,
-- and only for a check-in the server has recorded as passed.
create policy captures_insert_own_passed
on storage.objects for insert to authenticated
with check (
  bucket_id = 'captures'
  and (storage.foldername(name))[1] = auth_org_id()::text
  and (storage.foldername(name))[2] = auth.uid()::text
  and exists (
    select 1 from checkin_events c
    where c.id = ((storage.foldername(name))[4])::uuid
      and c.user_id = auth.uid()
      and c.outcome = 'pass'
  )
);
-- No select, update or delete policies on the bucket:
-- reads go through capture-url, deletes through retention-purge.
